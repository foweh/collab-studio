# Collab Studio 项目介绍

> 局域网实时协作创作工作室 —— 剧本 / 思维导图 / 故事 / 分镜，零配置，无需云端。

- 仓库：https://github.com/foweh/collab-studio
- 许可：MIT
- 运行环境：Node.js >= 18

---

## 一、项目定位与用途

Collab Studio（多机协作创作工作室）是一个**面向局域网的多人在线协作创作平台**。最初为高校学生组织的部门化内容生产场景设计，内置了吉林农业科技学院校易班学生工作站的 8 个部门定义。

它和一般"在线文档"的区别在于：

- **零配置、去中心化**：每台电脑执行 `node server.js` 即可；同一网段的节点通过 UDP 广播自动发现、自动组网，无需中心服务器、无需公网、无需注册。
- **实时协作**：基于 Socket.IO 的事件同步，剧本、思维导图、故事、分镜、白板等支持多人在线同时编辑。
- **不止是编辑器**：在创作编辑器之外，还包含素材库、设备管理、审核状态机、数据看板等组织协作能力。

### 典型使用场景

- 学生组织 / 社团的部门内容生产与协同编辑；
- 多人远程共同创作一个剧本 / 故事 / 分镜 / 思维导图；
- 局域网内的活动策划、任务流转（审核）与素材共享；
- 内容团队把"创作编辑器 + 审批流程 + 素材/设备台账"合到一处使用。

## 三、技术栈

- **后端**：Node.js (>=18) + Express + Socket.IO + UDP(dgram) + HTTPS
- **前端**：原生 JavaScript (ES Modules) + Canvas 渲染；第三方库全部本地化
  （Chart.js、jsPDF、JSZip、mammoth、marked、pdf.js、xlsx）
- **AI**：DeepSeek API（默认模型 `deepseek-chat`）
- **认证**：bcryptjs 密码哈希 + 会话 token
- **视频场景检测**：Python + Flask + PySceneDetect + TransNetV2
- **打包 / 部署**：Docker；`pkg` 打包为 Windows exe；Android（WebView + nodejs-project 副本）；NSIS 安装器

## 五、模块详解

### 后端核心（server.js）

- 解析命令行参数（`--port`、`--join`、`--data-dir`）。
- 启动 HTTP（默认 3000，自动跳转 HTTPS）、HTTPS（有证书时 443）、UDP 发现（41234）。
- 挂载 Socket.IO，处理全部实时事件（协作编辑、聊天、审批、部门、设备、素材等）。
- 启动视频场景检测的 Flask 子进程（可选，缺依赖时跳过）。
- 提供 HTTP 接口：素材上传（multer）、头像、二维码等。

### services/（业务服务）

| 文件 | 职责 |
| --- | --- |
| `auth.js` | 用户、bcrypt 密码、会话 token、角色权限（`canEdit` / `canComment` / `canView`） |
| `project.js` | 项目 CRUD、可见性（`private` 等）、操作历史撤回/恢复、项目类型与默认数据 |
| `department.js` | 8 部门定义与校验、把用户/项目归到部门 |
| `state-machine.js` | 通用审核 / 工作流引擎，每个流转步骤按角色（leader/vice/member/admin）授权 |
| `materials.js` | 素材库：分部门/分月存储、上传权限校验 |
| `devices.js` | 设备台账：借用 / 归还 / 维护 |
| `ai.js` | 调用 DeepSeek（`deepseek-chat`），带指数退避重试；配置存 `data/ai-config.json` |
| `annotation.js` | 批注 |
| `capcut-mate.js` | 与剪映智能剪辑 API 对接，生成剪映草稿 |
| `logger.js` | 操作日志 |

### 项目类型

`project.js` 内置多种项目类型与默认数据结构：

- 通用创作：`script`（剧本）、`mindmap`（思维导图）、`story`（故事）、`storyboard`（分镜）、`folder`、`project`
- 部门专属：`article`（推文）、`design-task`（设计任务）、`activity`（活动）、`meeting`（会议记录）、`audio-project`（音频项目）、`video-project`（视频项目）

### 前端（public/）

- 以 `app.js` 为核心组织：登录、在线用户、协作、聊天/群聊、管理面板、部门视图等。
- 各编辑器（`mindmap.js` / `script-editor.js` / `story-editor.js` / 分镜）各自独立。
- `dept-views.js` 负责部门工作台与数据看板；`tools.js` 是纯前端工具集。
- 第三方库统一放在 `public/vendor/`，离线可用。

### 视频场景检测（scenedetect-server/）

独立 Python 进程：`server.py`（Flask）封装 PySceneDetect + TransNetV2，后端通过子进程调用，按场景自动切分视频。缺 Python 依赖（如 OpenCV）时该功能自动跳过，不影响主服务。

## 六、运行与部署

### 本地运行

```bash
cd collab-studio
npm install
node server.js                 # 默认端口 3000，自动跳转 HTTPS
node server.js --port 3001     # 指定端口
node server.js --join 192.168.1.100:3000   # 加入已有节点
```

浏览器打开 `http://localhost:3000`，输入名字进入。多台机器各自 `node server.js`，通过 UDP 广播自动组网。

### Docker

```bash
docker compose up -d
```

映射 `3000`（HTTP）与 `41234/udp`（发现），挂载 `./data` 持久化；管理员密码通过环境变量 `ADMIN_PASSWORD` 注入。

### 打包 / 分发

- Windows 单文件：`npm run build`（`pkg` 打包为 `dist/CollabStudio/CollabStudio.exe`）。
- Android：`android/`（WebView 外壳 + 内嵌 nodejs-project）。
- Windows 安装器：`installer/`（NSIS + launcher）。

## 七、数据与配置

| 路径 | 说明 | 是否入库 |
| --- | --- | --- |
| `data/` | 运行时数据：users、projects、日志、权限、token、分组、素材索引、AI 配置等 | 否（.gitignore） |
| `uploads/` | 素材上传文件 | 否 |
| `ssl/` | 自签名证书 `cert.pem` / `privkey.pem` | 否 |
| `backup/` | 旧版 server 备份 | 否 |

| `.env.example` | 环境变量模板（端口等），可参照创建 `.env` | 是 |

端口约定：

- HTTP `3000`（自动跳转 HTTPS）
- HTTPS `443`（存在 `ssl/` 证书时启用）
- UDP 发现 `41234`
- 场景检测 Flask `5000` / `5001`
- 剪映 (capcut-mate) `9527`

上述端口均可通过环境变量覆盖（`PORT` / `UDP_PORT` / `HTTPS_PORT` / `SCENEDETECT_PORT`）。

## 八、权限模型

1. **全局角色**（`users.json` 的 `role`）：
   - `admin`（站长）：全部权限，含管理员面板。
   - `editor`（编辑者）：可编辑项目。
   - `commenter`（评论者）：可评论。
   - `observer`（观察者）：只读。
2. **部门角色**（`departmentId` / `deptRole`）：`leader`（部长）/ `vice`（副部长）/ `member`（干事），用于部门隔离与工作流授权。
3. **项目可见性**：项目带 `visibility`（如 `private`），配合 `project.js` 的查看/编辑/删除权限判定。
4. **消息权限**：非管理员给指定用户发消息，需管理员审批（`message-permissions.json`）。
5. **登录安全**：bcrypt 哈希、会话 token、找回密码审批、按 IP/用户/指纹的频率限制。

内置 8 个部门（可在 `services/department.js` 修改）：

| 部门 | 职责 |
| --- | --- |
| 传媒编导部 | 视频内容生产、活动直播导播、影视后期 |
| 采编宣传部 | 公众号运营、新闻采写、思政项目申报 |
| 文化设计部 | 平面视觉、文创、手绘、简单动画 |
| 秘书处 | 行政统筹、档案归档、物资管理、考勤 |
| 主持播音部 | 线下主持、音频栏目、配音、朗诵演讲 |
| 发展运营部 | 平台运维、易班 APP、轻应用、数据统计 |
| 多媒体工作部 | 抖音短视频、航拍、微电影 |
| 活动策划部 | 线上线下活动全流程策划与执行 |

## 九、开发约定：三份副本与 sync-build.js

为了同时支持"网页版 / Android 版 / 安装器版"，后端代码存在三份：

- 主版：`server.js` + `services/` + `utils/`
- Android 副本：`android/app/src/main/assets/nodejs-project/`
- 安装器副本：`installer/app/`

**约定：只修改主版，然后用同步脚本把后端同步到副本，避免三份代码漂移。**

```bash
node sync-build.js          # 同步 server.js / services/ / utils/ 并校验三者 SHA-256 一致
node sync-build.js --deps   # 同步的同时合并依赖
```

注意：`sync-build.js` 目前只同步**后端**（`server.js` / `services/` / `utils/`），**不包含 `public/` 前端**。若修改了前端，需要另行处理副本。
